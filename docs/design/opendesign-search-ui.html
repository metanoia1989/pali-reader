5 · 命中高亮

anuttaraṃ dhammacakkaṃ pavattitaṃ, appaṭivattiyaṃ samaṇena vā brāhmaṇena vā

读者输入 dhammacakkam（没有 ṃ）。索引存的是去音标的孪生串，位置表指回原文，所以高亮的是经文自己的拼法 dhammacakkaṃ——整个字形，包括那个他没打的 ṃ。

Evaṃ me sutaṃ — ekaṃ samayaṃ bhagavā sāvatthiyaṃ viharati

高亮用同一枚墨蓝：淡墨底 #e4ecf5 + 墨蓝字 + 权重 500。不加下划线、不加第二种颜色。命中在结果里永远整词高亮，不做逐字母高亮——逐字母在带音标的字上会碎成两半。

索引折叠的字符对（单向：索引折叠，原文不动）

ṃ → mṅ → nñ → nṭ → tḍ → dṇ → nā → aī → iū → uś → s大小写不敏感

折叠是有代价的：sati 会连 sāti 一起搜出来。所以排序是「带音标的精确匹配在前，折叠匹配在后」，而不是过滤掉后者——读者能看见原文，就永远能自己判断。字段里的字永不自动改写，也不做自动更正。

6 · 两段理由

模式开关为什么不做成四个标签。56px 的顶栏里，站名和账号菜单已经占了两端，剩下 560px 要给输入框；四个中文标签横排放进去，输入框只剩 300px 不到，而且标签一旦固定在字段里，就永远占着宽度——读者 90% 的时间根本不在切模式。所以字段右端只留一个当前范围按钮：它的形状是分段控件的一段（圆角、贴边、带刳号），所以看得出「还有别的段」；它永远写着当前模式，所以「我现在在搜什么」从不隐藏；点开是一张 308px 的小菜单，四行各带一句范围说明和快捷键，切换是一次点击。为了让它不必被点开也能读懂，模式同时写进另外两个地方——字段左端那个小图示，和占位符的措辞（「在本章内搜索」／「在巴利全文里搜索」）。范围因此在一处可点、三处可见，不花一个额外像素。再补一个不用读字的信号：本章是暖砂底（安全、就在眼前），另外三种是淡墨底 + 墨蓝字（你在搜整个藏）。

一行结果里为什么是这些东西。一行两排字，上排是经文原文，下排是它对应的译文，右侧是落点，三样东西各回答一个问题：这是不是我找的那句（原文，所以用衬线——在面板里也保持衬线，这样一眼就知道哪一行是经文、哪一行是界面）、它是什么意思（译文，无衬线、11.5px 起，扫读用）、点了会落到哪里（经文名 + 段号，永远靠右、不对齐左端，因为它不是内容）。全文模式每段只出一条，不是一个命中一条：一个词在同一段里出现五次，读者要的是那一段，不是五行一样的东西；于是行数由段落数决定，命中总数放进表头（「12 段 · 47 处」），点哪一行都跳到那一段。面板固定只显示 5 行，页脚负责说真话——本地模式写「仅在本章内查找」并给一个扩大范围的入口，全藏模式写「显示 5 / 12 段」并给一个通往完整结果的入口。字段永远不变成结果页，但它也永远不假装结果只有这些。
